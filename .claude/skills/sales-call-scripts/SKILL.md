# Sales Call Scripts

Produce call-ready scripts and talk tracks a rep can glance at mid-conversation: openers that set an agenda in under 90 seconds, question sequences that surface and quantify pain, demo narratives that map features back to that pain, trial closes that test temperature without pressure, and closing language that books a concrete next step before the call ends. Every script must sound like a person talking, not marketing copy read aloud — short sentences, contractions, pauses marked, and branches for the two or three most likely prospect responses at each decision point.

## When to use this skill

Use this skill when the user wants:
- A discovery call script or question list for a first or second conversation
- A demo call talk track, including how to open, sequence, and close a product demo
- A closing/proposal-review call script with trial closes and next-step language
- Voicemail scripts (first touch, post-no-show, re-engagement)
- Mid-call pivots for common objections ("we already use X", "no budget", "send me info")
- A call-prep one-pager for a specific named account or persona

Do NOT use this skill for adjacent jobs — route instead:
- Written outreach to book the call → **cold-email-outreach** or **linkedin-outreach**
- Deep objection rebuttals, battlecards, and competitive counters → **objection-handling** (this skill covers only the 15–30 second mid-call pivot that keeps the conversation moving)
- Scoring whether a lead is worth a call at all (BANT/MEDDIC criteria) → **lead-qualification** (this skill embeds qualification questions inside a script but does not design the scoring model)
- The written proposal or pricing document discussed on a closing call → **sales-proposals**
- What to send after the call (recap emails, nurture cadence) → **follow-up-sequences**
- One-to-many presentation scripts → **webinar-scripts**
- Where this deal sits and what stage it should be in → **sales-pipeline-management**

## Inputs to gather

Ask for these before drafting. If the user can't answer, use the stated default and flag the assumption at the top of the deliverable.

1. **Call type**: discovery, demo, or closing? (Default: discovery — it's the highest-leverage script.)
2. **Product and one-sentence value proposition.** No default — this is required. If missing, ask.
3. **Who's on the other end**: title, seniority, buyer vs. user, how many people on the call. (Default: single mid-level manager who influences but doesn't sign.)
4. **Deal size / sales motion**: transactional (<$5K ACV, 1–2 calls), mid-market ($5K–$50K, 3–5 calls), or enterprise (>$50K, 6+ calls). This sets call length and how hard the close can be. (Default: mid-market.)
5. **Call length booked**: (Defaults: discovery 30 min, demo 45 min, closing 30 min.)
6. **Top 2–3 pains the product solves**, ideally in the customer's words. (Default: derive from the value prop and say so.)
7. **What was already learned** — prior calls, email thread, inbound form answers. (Default: assume cold-ish, only firmographic knowledge.)
8. **The one next step the rep wants** from this call. (Defaults: discovery → demo booked with a power sponsor added; demo → proposal review call; closing → verbal commit plus paperwork date.)
9. **Competitor or status quo** the prospect most likely uses today. (Default: "doing it manually / spreadsheet.")
10. **Tone constraints**: challenger-direct vs. consultative-warm. (Default: consultative with one or two direct moments.)

## Process

1. **Confirm call type and success criterion.** Write one line at the top of your working draft: "This call succeeds if ___." For discovery: 2–3 quantified pains uncovered and a demo booked. For demo: prospect ties at least one shown capability to their own stated pain, and a proposal-review call is booked. For closing: a decision — yes, no, or a dated path to yes. Never "build rapport" or "share information" — those aren't outcomes.

2. **Time-box the call into blocks.** Allocate minutes before writing a word. Discovery (30 min): open/agenda 3, their-world questions 15, fit summary + light positioning 5, next step 5, buffer 2. Demo (45 min): open/agenda 3, discovery recap + confirm 5, demo story 25 (max 3 chapters), pricing preview if asked 5, next step 5, buffer 2. Closing (30 min): open 2, recap of agreed value 5, proposal walkthrough 10, trial close + objections 8, next-step lock 5. If a section's script would blow its time box when read aloud (~140 words/minute), cut it.

3. **Write the opener with an upfront contract** (see PPO template below). It must state purpose, proposed agenda, time check, and — critically — name the decision point at the end: "...and at the end, we'll decide together whether it makes sense to keep talking. Fair?" Getting agreement to a decision up front is what makes the close at minute 25 feel natural instead of pushy.

4. **Build the question flow.** Pick the framework by deal motion: SPIN for consultative mid-market/enterprise discovery; gap selling's current-state → future-state → gap math when the pain is quantifiable in dollars or hours. Draft 8–12 questions (top reps ask roughly 11–14 targeted questions per discovery call; under 6 signals pitching, over 18 feels like an interrogation). Sequence them broad → narrow → quantified. For each of the 3–4 most important questions, script the follow-up probe ("Tell me more about that", "What does that cost you in a typical month?", "Who else feels that?").

5. **Add branch logic at 2–3 decision points.** Real calls fork. Script the fork: "IF they name a pain → go deep with implication questions. IF they say 'everything's fine' → use the provocation line: 'That's great — most [title]s I talk to say [common pain]. What are you doing differently?'" Every branch must rejoin the main script.

6. **For demos, structure as story chapters tied to discovered pain.** Never write a feature tour. Each chapter = one pain from discovery, in tell-show-tell form: (a) restate their pain in their words, (b) show only the 2–4 clicks that resolve it, (c) state the outcome with a number, then (d) check in: "How does that compare to how you handle it today?" Cap at 3 chapters. If discovery data is missing, the script's first block must be a 5-minute mini-discovery — flag this to the user as a risk.

7. **Insert trial closes at temperature-check moments** — after each demo chapter, after the fit summary in discovery, after the pricing walkthrough. A trial close asks for an opinion, not a decision: "Is this the kind of thing that would actually move the needle for your team?" Script the two likely answers: warm ("What specifically stood out?") and cool ("Sounds like something's missing — what is it?"). 2–3 trial closes per call; more reads as needy.

8. **Script mid-call objection pivots** for the 3 objections most likely for this product/persona. Use the AER pattern (Acknowledge–Explore–Redirect, ~20 seconds): acknowledge without agreeing, ask one clarifying question, redirect to the agenda. These are traffic control, not rebuttals — if the user needs full counter-arguments, point them to **objection-handling**.

9. **Write the next-step lock.** The single highest-leverage moment: deals with a concrete next meeting booked on the call advance at roughly 2x the rate of "I'll send some times." Script the exact words: summarize value in their words → propose the specific next step with a calendar action → confirm attendees → book it live ("Do you have your calendar handy? I'm looking at Tuesday at 10 or Wednesday at 2."). Include a fallback for "let me check with my team": get a named date for their internal conversation and book the follow-up for the day after.

10. **Write the voicemails** (see template): first-touch (18–30 seconds, 50–75 words), no-show recovery, and going-dark re-engagement. Every voicemail names a reason relevant to them, gives one number/next action, and states the callback number twice, slowly. Expect callback rates in the 1–5% range — the voicemail's real job is priming the follow-up email, so note which email it pairs with (hand that email itself to **follow-up-sequences**).

11. **Read the full script aloud mentally.** Kill any sentence over ~20 words, any jargon the prospect wouldn't use, and any paragraph the rep must recite verbatim for more than 30 seconds. Convert recitations into bullet talk tracks. Then run the Quality checklist below and deliver in the Output format.

## Frameworks & templates

### SPIN question flow (Rackham)

- **Situation** (max 2–3; research should answer most): "How is your team handling [process] today?" "How many people touch that?"
- **Problem**: "What breaks first when volume spikes?" "Where does that process slow down?"
- **Implication** (the money layer — spend the most time here): "When that report is late, what happens downstream?" "What's that costing you per month in [hours/dollars/churn]?"
- **Need-payoff** (prospect states the value themselves): "If you got those 10 hours a week back, what would the team do with them?" "How would fixing this change your Q4 target?"

Rule: never ask an Implication question about a Problem the prospect hasn't confirmed. Sequence per pain thread: 1 Situation → 1–2 Problem → 2–3 Implication → 1 Need-payoff.

### Gap selling math

Current state (facts + felt pain + measurable cost) → Future state (what "fixed" looks like, in their metrics) → **Gap = future minus current, in dollars/hours/risk**. The gap is the price justification. Script the moment the rep says the gap out loud: "So today it's ~40 hours a month and two churned accounts a quarter; you want that under 10 hours and near-zero churn from this cause. That gap is roughly $180K a year. Did I get that right?" If the gap is smaller than ~3x the annual price, the script should include a disqualification branch — walking is a valid outcome.

### PPO opener / upfront contract (fill-in-the-blank)

> "Thanks for making time, [Name] — we've got [25] minutes, right? Here's what I was thinking. **Purpose:** you mentioned [trigger/pain from booking context], so I want to understand how [process] works on your side today. **Plan:** I'll ask questions for most of it, share how teams like [peer company] handle it if it's relevant, and leave [5] minutes at the end. **Outcome:** by then we should both know if a deeper look makes sense — and if it doesn't, I'll tell you straight and we part friends. Anything you want to make sure we cover?"

Under 90 seconds spoken. The last question matters: their addition reveals their real agenda.

### Demo chapter template (tell–show–tell)

> **Tell:** "On our last call you said [exact quote about pain], and that it costs you about [number]. Watch how that works here."
> **Show:** [2–4 clicks max — name the clicks in the script: "From the dashboard, click Reports → Auto-schedule. That's it."]
> **Tell:** "That's the whole workflow — what took [old time] now takes [new time]."
> **Check:** "How does that compare to what your team does today?" → IF warm: "Who else on your side would care about this?" IF flat: "Seems like that one didn't land — which part of your workflow did I get wrong?"

### Trial-close lines (pick 2–3 per call)

- "Is what you've seen so far in line with what you hoped this would do?"
- "On a gut level — could you see your team using this?"
- "If the pricing works, is there anything else that would keep this from being a fit?"
- "What would need to be true for this to be a yes?"
- "How do you think [boss/stakeholder] would react to this?" *(doubles as a multi-threading probe)*

Script both branches for each one used. Warm → advance ("What stood out most?"); cool → excavate ("Sounds like something's off — what did I miss?"). Never answer a cool response with more pitching.

### Mid-call objection pivots (AER, ~20 seconds each)

- **"We already use [competitor]."** → "That makes sense — a lot of our customers came from [competitor]. (A) Out of curiosity, what's working well, and what made you take this call anyway? (E) Got it — let's spend our time on [that gap], then. (R)"
- **"We don't have budget."** → "Fair — I wouldn't expect budget for something you haven't valued yet. (A) If the math showed this pays for itself in [X months], is there a path, or is it frozen no matter what? (E) Then let's figure out whether the math is even real before we worry about it. (R)"
- **"Just send me some information."** → "Happy to. (A) So I send the right thing — which part felt most relevant: [pain A] or [pain B]? (E) I'll send that today. Most people have questions once they read it — let's put 15 minutes on the calendar now, and cancel if you don't. (R)"

### Next-step lock (fill-in-the-blank)

> "Let me play back what I heard: you're dealing with [pain 1] and [pain 2], costing roughly [number], and you'd want that fixed by [their timeline]. Given that, the logical next step is [specific meeting] with [named attendee — e.g., 'your head of ops, since she owns that workflow']. I'm looking at [Tue 10:00] or [Wed 14:00] — which works? ... Great, invite's coming now; can you forward it to [attendee] while we're on?"
> **Fallback if "let me check internally":** "Totally fair. When are you talking to [them]? [Thursday.] Then let's hold Friday at [time] — if Thursday changes things, we'll cancel. Better than chasing calendars for two weeks, right?"

### Voicemail scripts

**First touch (18–30 sec, 50–75 words):**
> "Hi [Name], this is [Rep] at [Company]. I'm calling because [specific, researched reason — e.g., 'you just opened a second location, and that usually breaks the inventory process']. We helped [peer company] cut [metric] by [number]. I'll send a short email with the details — my number is [number, slowly]. Again, [Rep], [Company], [number]. Thanks."

**No-show recovery (≤20 sec):**
> "Hi [Name], [Rep] from [Company] — we had [time] on the calendar today; no worries, things move. I'm sending two new times by email right now. If neither works, reply with one that does. [Number]. Talk soon."

**Going dark (≤25 sec, permission-to-close):**
> "Hi [Name], [Rep] here. We talked about [pain] a few weeks back and I haven't been able to reach you since. Usually that means priorities shifted — completely fine, just tell me and I'll close the file. If it's still live, [one new reason — new feature, deadline, case study]. [Number], twice: [number]."

### Closing-call spine (proposal-review, 30 min)

1. **Open (2 min):** "Goal for today: walk the proposal, answer everything, and land on a decision — yes, no, or exactly what has to happen before yes. Fair?"
2. **Value recap before price (5 min):** Restate the gap math from discovery *before* showing numbers: "You sized this problem at [$X/year]. The proposal is [$Y/year]. So we're talking about a [X÷Y]-to-1 return — keep that ratio in mind as we walk through it."
3. **Walk the proposal by outcome, not line item (10 min):** For each section: what it solves → what it costs → check-in. (The document itself comes from **sales-proposals**.)
4. **Trial close (2 min):** "Money aside for a second — is this the solution you want?" (Separates product objections from price objections; script both branches.)
5. **Surface the hidden blockers (6 min):** "If you took this to [signer] today, what would they push back on?" and "Who haven't we talked to who could slow this down?"
6. **Lock (5 min):** Ask directly — "What I'd suggest: we target [date] for signature, which means legal review starts [date] and we kick off [date]. Does that timeline hold on your side?" Then book the paperwork-review call before hanging up.

### Worked example — first 4 minutes of a discovery script

Product: ShiftPilot, scheduling software for multi-location restaurant groups. Prospect: Dana, Director of Ops, 12 locations, booked via inbound demo request. This shows the required notation in action:

> **[0:00–1:30] Opener**
> "Dana, thanks for grabbing time — we've got 30 minutes, still good? (pause) Great. You requested a demo, so here's my plan: I'll ask about how scheduling works across your 12 locations today, because ShiftPilot lands very differently depending on that. If it looks like a fit, I'll show you the two pieces that matter most for groups your size, and we'll book a full demo with anyone else who'd need to see it. And if it's not a fit, I'll say so and point you somewhere better. Anything you want to make sure we hit?"
> *(let them answer — write down whatever they add; cover it or the close will stall)*
>
> **[1:30–4:00] First pain thread**
> "So — who actually builds the schedule at each location today, and in what tool?" **(S)**
> "When a GM calls out sick on a Friday, what happens to that week's schedule?" **(P)**
>    **IF a real story comes out** → "How often does that happen across 12 locations in a month?" **(P)** → "And when shifts go uncovered, what does that do to that night's revenue — ballpark?" **(I)**
>    **IF "honestly, it mostly works"** → "That's genuinely rare — most 10-plus-location groups tell me GMs spend 4 to 6 hours a week on schedules. What's your setup doing differently?" *(either they reveal the cost they've normalized, or they're truly fine — disqualify gracefully)*
> "If every GM got those hours back, where would you point them?" **(N)**

Note what the example does: verbatim opener, labeled SPIN stages, both branches written, a quantifying probe inside each branch, and a disqualification path that doesn't burn the relationship. Reproduce this density for every pain thread in the deliverable.

## Output format

Deliver a single markdown document:

1. **Header block**: call type, prospect/persona, booked length, the one success criterion, and any assumptions made from defaults.
2. **Timing map**: table of call blocks with minute allocations.
3. **The script**, block by block, using this notation:
   - Plain text = verbatim lines the rep can say as written
   - `[BRACKETS]` = fill-ins the rep customizes pre-call
   - **IF/THEN branches** indented under the line that triggers them
   - `(pause)`, `(let them answer)` = delivery cues
   - Bullet lists = talk-track points to improvise from, not recite
4. **Question bank**: the 8–12 questions labeled by framework stage (S/P/I/N or current/future/gap), with follow-up probes for the top 3–4.
5. **Objection pivot card**: the 3 scripted AER pivots.
6. **Next-step lock + fallback** verbatim.
7. **Voicemail scripts** relevant to this call type.
8. **Pre-call prep checklist**: 5–7 items the rep completes before dialing (research fields to fill the `[BRACKETS]`, tech check for demos, attendee list confirmed).

## Quality checklist

Verify every item; fix the script until all pass.

- [ ] Opener states purpose, plan, time, and a named end-of-call decision point, and runs under 90 seconds spoken (~200 words max)
- [ ] The call has exactly one written success criterion, and the final block asks for it explicitly
- [ ] Question count is 8–12 for discovery (5–8 recap/check questions for demo), sequenced broad → narrow → quantified
- [ ] At least 3 questions probe cost/impact (Implication or gap-math), not just facts
- [ ] Script keeps rep talk share ≈ 40–45% on discovery (word-count the verbatim rep lines against expected answer time to sanity-check)
- [ ] Every demo chapter opens by restating a discovered pain in the prospect's words and ends with a check-in question
- [ ] No more than 3 demo chapters; no feature shown that isn't tied to a stated pain
- [ ] 2–3 trial closes present, each with scripted warm and cool branches
- [ ] Exactly 3 objection pivots, each ≤ ~60 words and ending by redirecting to the agenda
- [ ] Next-step lock proposes a specific meeting with named attendees and two concrete time slots, plus a scripted fallback
- [ ] Voicemails are ≤75 words, include one prospect-specific reason, and state the callback number twice
- [ ] No verbatim rep monologue exceeds 30 seconds (~70 words) anywhere in the script
- [ ] Every sentence survives the read-aloud test: ≤20 words, contractions used, zero unexplained jargon or internal product codenames
- [ ] All `[BRACKETS]` fill-ins appear in the pre-call prep checklist so the rep fills them before dialing
- [ ] Timing map totals to the booked call length with ≥2 minutes of buffer

## Common mistakes

- **Writing an essay, not a script.** Dense paragraphs are unusable at a glance mid-call. Verbatim lines only where wording is load-bearing (opener, trial closes, pivots, lock); everything else is bullets.
- **Demo-first structure.** Scripting the product tour and sprinkling questions on top. If discovery hasn't happened, the demo script must start with a mini-discovery block — otherwise you're narrating features to strangers.
- **Situation-question overload.** Ten "how many seats do you have?" questions the rep could have Googled. Cap Situation questions at 3 and push the count into Implication territory, where deals are actually won.
- **Trial close written as a real close.** "Ready to sign?" at minute 20 of a discovery call torches trust. Trial closes ask for opinions ("does this resonate?"), never for commitments.
- **The floating next step.** Ending with "I'll follow up with some times" — the classic deal-killer. The script must book the meeting on the call, calendar open, or execute the dated fallback.
- **Objection pivots that argue.** A mid-call pivot that launches a 3-minute rebuttal derails the agenda. Acknowledge, ask one question, redirect — full rebuttals live in **objection-handling**.
- **Ignoring the multi-threading moment.** When a prospect says "my boss would care about this," the script must seize it ("Should we get her into the next call?"). Single-threaded deals stall; script the invite.
- **Voicemails that pitch.** A 60-second feature monologue gets deleted at second 8. One relevant reason, one number, callback number twice, out by second 30.
- **One script for every deal size.** A hard next-step lock is right for a $6K deal and wrong for a $300K enterprise motion, where the lock is a mutual-action-plan review. Match assertiveness to ACV and sales-cycle stage.
- **Scripting only the happy path.** If every prospect answer in the script is cooperative, it will shatter on the first "we're fine, actually." Every key question needs the cool-response branch written out.
